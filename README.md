# Slot Booking Bot

Telegram-бот для записи на встречи. Владелец публикует свободное время для контакта или категории пользователей, участник выбирает слот и отправляет заявку, владелец подтверждает или отклоняет её. Подтверждённую встречу можно отменить до её начала.

Kotlin, Java 21, Spring Boot, PostgreSQL 18. Миграции — Flyway, тесты — JUnit 5 и Testcontainers.

## Запуск

Нужны JDK 21, запущенный Docker с Compose и токен бота от [BotFather](https://t.me/BotFather). Бот работает в личных чатах через long polling; публичный адрес сервера не нужен.

Из корня репозитория:

```sh
cp .env.example .env
```

В `.env` задайте `DB_PASSWORD`, укажите `TELEGRAM_BOT_TOKEN` и включите `TELEGRAM_BOT_ENABLED=true`. По умолчанию бот отключён. `BOOKING_TIME_ZONE` задаёт часовой пояс всех слотов, исходное значение — `Europe/Moscow`. Если порт 5432 занят, измените `DB_PORT`.

```sh
docker compose up -d --wait postgres
bash ./gradlew bootRun
```

В Windows PowerShell вместо `bash ./gradlew` используйте `.\gradlew.bat`. Gradle устанавливать отдельно не нужно. Приложение читает `.env` и само применяет миграции. После запуска откройте бота и отправьте `/start`.

Для остановки приложения нажмите Ctrl+C, для остановки БД выполните `docker compose down`. Данные сохраняются в Docker volume. `.env` с токеном и паролем исключён из Git.

## Попробовать вдвоём

1. Оба пользователя отправляют боту `/start`.
2. Участник вызывает `/invite` и передаёт ссылку владельцу. Владелец открывает её и нажимает «Добавить в контакты».
3. Владелец вызывает `/new_slots`, выбирает участника и вводит будущий интервал в формате `ГГГГ-ММ-ДД ЧЧ:ММ-ЧЧ:ММ`. На шагах места и описания можно отправить `/skip`. Затем задаёт лимит `1` и подтверждает публикацию.
4. Участник открывает `/slots`, выбирает слот и подаёт заявку. Комментарий и предложение места можно пропустить через `/skip`; в конце нужно подтвердить отправку.
5. Владелец открывает `/requests` и подтверждает заявку. Участник видит подтверждение в `/bookings`.
6. Участник отменяет встречу кнопкой в карточке брони. До начала встречи слот снова доступен через `/slots`. Можно подать новую заявку и проверить её отклонение владельцем.

Для публикации группе владелец создаёт `/new_category Друзья`, добавляет контакт кнопкой «Добавить участника» и выбирает эту категорию при создании слотов. `/draft` возвращает к незавершённому диалогу, `/cancel` отменяет черновик, `/help` показывает команды.

Уведомления и напоминания пока не реализованы: обе стороны проверяют статусы через `/bookings` и `/requests`. Предложенное участником место сохраняется в заявке, но его согласование ещё не реализовано.

## Проверка без Telegram

Достаточно JDK 21 и запущенного Docker. `.env` и токен не нужны: Testcontainers поднимает отдельную PostgreSQL, обращения к Telegram подменяются в тестах.

```sh
bash ./gradlew build
```

Тесты проверяют обработку Telegram-событий, публикацию, цикл бронирования, права доступа, повторные действия и одновременные заявки на один слот. Для отдельного прогона сценариев бронирования:

```sh
bash ./gradlew test --tests '*TelegramBookingIntegrationTest'
```

## Устройство

Код сгруппирован по предметным областям: `booking`, `slot`, `user`, `contact`, `category`. Telegram-адаптер отвечает за диалоги и сообщения, сервисы — за бизнес-правила и транзакции. Двойное бронирование предотвращают блокировки и уникальный индекс PostgreSQL. Черновики хранятся в БД и доступны после перезапуска в течение 24 часов.

Подробности: [контакты и категории](docs/telegram-directory.md), [публикация слотов](docs/slot-publication.md), [бронирование](docs/telegram-booking.md).
